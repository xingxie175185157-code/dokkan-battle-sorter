## 这是什么

《七龍珠爆裂激戰》/《龙珠爆裂大战》（Dragon Ball Z: Dokkan Battle）的战斗里，一支 7 人队伍
每回合只有 **连续 3 个槽位** 的人出场，起始槽位每回合后移 3 格，7 回合一个循环。
手动心算「第 8 回合谁能上、想让 XX 第 8 回合上场前面该怎么调」非常痛苦。

这个工具把它变成可视化操作：

- 填入 7 人（自己 6 人 + 好友助战 1 人，同名卡可占两个槽位）→ 一次列出**任意回合数**的出场顺序
- 每回合 3 人可以**拖动换位**，改动会**连锁重算之后所有回合**
- 想把某个角色放到**指定回合的指定位置**？拖过去，程序**自动反推出前面需要怎么调**
- 做不到的时候**明确拒绝并告诉你原因**，不给你一个「以为成功其实失败」的结果

## 使用说明

### 一、槽位轮转规则

7 个槽位 = **自己的队伍 6 人 + 好友助战 1 人**，每回合取**连续 3 个**上场，起始槽位每回合后移 3 格。周期为 **7 回合**：

| 回合 | 上场槽位 | 回合 | 上场槽位 |
|:---:|:---:|:---:|:---:|
| 1 | **1 · 2 · 3** | 5 | **6 · 7 · 1** |
| 2 | **4 · 5 · 6** | 6 | **2 · 3 · 4** |
| 3 | **7 · 1 · 2** | 7 | **5 · 6 · 7** |
| 4 | **3 · 4 · 5** | 8 | **1 · 2 · 3** ↺ |

> 起始槽位 = `(3 × (回合号 - 1)) mod 7`。第 8 回合与第 1 回合完全一致，之后循环。

**关键推论**：相邻两回合的上场窗口**完全不重叠**（1-2-3 → 4-5-6 → 7-1-2 …），
所以「第 2 回合要上的人，第 1 回合根本碰不到」。这是所有排布约束的根源。

### 二、填人与改序

1. 左侧「**图鉴**」搜索角色，点 `＋` 加入队伍空位（或直接拖进队伍格）
2. 「**我的**」页签可自建角色，也保存从图鉴收藏来的卡
3. 中间「**队伍初始顺序**」可拖拽调整 7 个槽位的初始归属
4. 右侧「**回合推演**」列出每回合的 3 人，**拖动卡片即可在本回合内换位**

> 从角色库拖卡进队伍格是**放入**语义：这张卡落在该槽位，原来的角色被替换。
> 同一张卡可以再拖一次放进另一个槽位 —— 那就是「自己一张 + 助战一张」的同名双角色（最多两张）。

> 改序的本质是**交换这三人的槽位归属**，因此之后所有回合都会连锁重算；
> 已经过去的回合显示保持不变（不会被后续改动倒灌）。

### 三、拖到指定回合（自动反推）

把任意角色（图鉴卡 / 我的卡 / 队伍格 / 牌序条 / 其他回合的卡）**拖到目标回合的某一格**：

- **可行** → 自动调整前置回合，然后：
  - 被自动调整的格子标 **「前置调整」**（金色）
  - 目标格标 **「目标位」**（绿色）
  - 9 秒后自动淡出，你一动手改序就立即清除
- **不可行** → 拖拽时显示**禁止光标**，底部提示条实时说明原因：

  > 不可行：超级赛亚人3孙悟空 在第 1 回合开始前只可能位于槽 5，而该回合上场的是槽 1 / 2 / 3。

反推算法会**尽量把改动推迟到最靠后的回合**，能不动你前面的排布就不动。
拖进来的角色若不在队伍里且有空位，会**自动补进队伍**（只填空位，保留你已有排布）。

### 四、编队（队伍预设）

队伍区顶部有一排**编队快捷位**，用来存常用的整套队伍：

1. 摆好 7 人（含初始顺序）→ 点 **「＋ 存为编队」** → 起个名字 → 保存
2. 之后点任意一个编队，就能**整套换人**，并按其初始顺序重新推演
3. 鼠标悬停在编队上，会出现 **✎**（重命名）和 **✕**（删除）；把鼠标停在编队上还能看到完整名单

**编队里存的是什么**：**「队伍里有哪 7 个人」+ 他们的初始槽位顺序 + 队长 / 助战标记**。
回合数、以及你手动拖出来的回合排程**不会**被保存 —— 载入后是按初始顺序重新推演的干净状态。

细节：

- 每个编队下方有 **7 格属性指纹**（按槽位顺序的色条），扫一眼就能认出是不是那套队；
  队长 / 助战对应的那一格会**多一圈描边**（同一人兼任时套两层）
- 当前队伍对应的那套编队会**高亮为「当前」**；队伍被改动后高亮自动消失
- 同一套编队不会重复保存（同 7 人但队长不同算两套）；空队伍不允许保存
- 编队和角色收藏一起存在浏览器本地，也一起走「导出 / 导入预设库」

### 五、队长 / 助战

队伍区上方的 **👑 队长 / 🤝 助战** 两个下拉框，可从当前队伍的角色里各指定一名：

- 自己的队伍 **6 人** + 好友**助战 1 人** = 7 个槽位，所以**同一个角色允许出现两张**
  （自己一张 + 助战一张），最多两张；选择器里同名两张只占一项，并标出它占了哪几个槽位
- **队长与助战可以是同一名角色** —— 这时该角色的格子上会同时显示「队长」「助战」两枚徽标
- 标记**跟着角色走，不跟着槽位走** —— 拖动改初始顺序时标记不会串位
- 显示位置：**队伍格右上角**、**当前牌序条**、**每一张回合卡片**、**出场回合汇总**
  （一眼就能看出每回合上场的是谁当队长）
- 存编队时一并保存，载入编队时一起恢复；角色被移出队伍时标记**自动摘掉**
- 数据保存的是统一 key（`r:<图鉴id>` / `p:<自建id>`），与队伍成员同一套写法；
  内部字段名沿用 `friend`（对应游戏内的「フレンド / Friend」），界面上一律叫「助战」

### 六、其它

- **语言**：标题栏语言按钮循环 `中文 → English → 中英`
- **回合数**：右侧输入框改回合数，或点「继续推演」往下加
- **导出 / 导入**：导出的 JSON 里同时含角色（`presets`）与编队（`teams`），换设备直接导入即可
- **帮助**：标题栏 `?` 查看内置说明

## 图鉴数据

1458 张角色卡，字段：中文名、英文名、称号、稀有度、属性、类别、头像、链接技能、分类、实装日期。

```
角色名中文化    1458 / 1458  = 100%
链接技能         133 / 133   = 100%
分类              99 / 99    = 100%
稀有度分布      LR 198 / UR 829 / SSR 122 / SR 160 / R 113 / N 36
```

**中文怎么来的**（这游戏**没有中文维基 / 中文数据库**，是三层拼出来的）：

| 层级 | 做法 | 覆盖 |
|---|---|---|
| 链接技能、分类 | 取官方**繁体中文**名表转简体 | 100% |
| 角色名 | 约 350 条术语表，按「最长优先 + 字母数字边界」逐词对照替换 | 100% |
| 角色称号 | 卡面 flavor text（1390 条几乎不重复），**保留英文** | — |

⚠️ 角色名为**算法生成**，与游戏内文本可能存在出入（尤其意译名、地区译名分歧）。
以游戏内实际文本为准，欢迎提 Issue 修正译名。

**数据来源**：[DOKKAN.FYI](https://dokkan.fyi)（非官方粉丝资料站，其 `robots.txt` / `llms.txt`
允许自动化读取公开页面）。图像为**第三方 CDN 外链**，本仓库不存储任何图片。

## 参与开发

### 环境

- Node.js **≥ 18**（`tests/verify.mjs` 用到内置 `fetch`）
- 应用本体**零依赖**；仅 jsdom 测试需要 `npm install`
- jsdom **版本不限**：`tests/dom.mjs` 对 jsdom ≥ 27 用 `requestInterceptor`，
  对 24~26 回退到 `ResourceLoader` 子类（已用 24 与 30 双版本验证）

### 测试

改完代码**三套测试都要跑**：

```bash
npm test              # 全部

npm run test:engine   # 引擎回归 144 项：槽位轮转 / 连锁重算 / 反推可行性 / 编队规整与指纹 / 队长助战 / 同名双角色
npm run test:static   # 静态校验 77 项：DOM id 契约 / 字段完整性 / 索引解析 / 导出格式 / 标记显示点
npm run test:dom      # 真实页面 128 项：加载无报错 / 图鉴渲染 / 收藏 / 四种拖拽 / 编队增删改与载入 / 队长助战 / 同名双角色
```

CI 在每次 push 与 PR 上跑同样的三套（见 `.github/workflows/ci.yml`）。

### 数据管线

```bash
npm run crawl     # 抓取 dokkan.fyi → data/raw-roster.json + data/enums-en.json
npm run build     # 词典中文化 → roster.js + data/report.txt
npm run rebuild   # 上面两步一起
```

想修译名：改 `tools/i18n-zh.json` 后 `npm run build` 即可，无需重新抓取。
`data/report.txt` 会列出**未被词典覆盖的英文残留**，是补词表的主要线索。

### 关键不变量

改引擎时请守住这几条，它们都有对应回归用例：

1. 回合卡片**渲染必须读快照** `state.turns[t]`，不能读 `state.deck`
2. 要把某回合排布写回牌序，必须用 `deckAt(k)` 从 `state.team` **重放历史快照**重建，
   直接读 `state.turns[k]` 会在跨回合改序时**丢人 + 造重复**
3. 新增引擎函数要写在 `function startSlot` 与 `渲染：预设库` 之间（测试按此切片提取引擎）
4. 读取队伍成员一律用 `resolve()` / `nameOf()` / `typeOf()` / `dispName()`（统一 key：
   图鉴 `r:<id>`、自建 `p:<id>`）；`byId()` 只适用于自建卡的编辑 / 删除路径
5. 角色 key 格式：`"r:<图鉴id>"` / `"p:<自建id>"`，旧裸 id 视为自建卡（向后兼容）
6. **写入 `state.team` 时一律写统一 key**，不要写裸 id。
   曾出现过「＋ 加入」写 `p:xxx` 而「自动填满」写 `xxx` 的不一致，
   会让同一套队伍算出两种指纹（现已修复并在读档时统一归一化）

### 对外接口

`window.DokkanSorter`（版本 `2.4.0`）：

```js
getRoster()                    // 图鉴数组
rosterSize() / isRosterReady()
searchRoster(keyword, opts)    // 搜索图鉴
card(key)                      // 统一 key → 卡对象
setTeamByRosterIds(ids)        // 按图鉴 id 设队伍
setTeamByNames(names)          // 按名字设队伍
getState()                     // { team, deck, turns, turnCount, leader, friend }
getPlan(key, turn, pos)        // 反推试算（纯函数，无副作用）
setTurnCount(n) / rebuild() / render()
addPresets(list) / removePreset(id)
getNameMode() / setNameMode('zh'|'en'|'both')

// 编队（队伍预设）
getTeams()                     // 全部编队（含各自的 leader / friend）
saveTeam(name)                 // 把当前队伍存成编队，返回新编队（重名/空队伍返回 null）
applyTeam(id)                  // 载入编队（连队长 / 助战一起恢复）
removeTeam(id)                 // 删除编队
addTeams(list)                 // 批量导入编队
getTeamSignature()             // 当前队伍的成员指纹

// 队长 / 助战
getRoles()                     // { leader, friend }，返回前会与队伍对齐
setLeader(key) / setFriend(key)   // 设标记；不在队伍里 → false（两者可以是同一角色）
setRoles(leader, friend)       // 一次设两个，返回 { leader:bool, friend:bool }
importBundle({ presets, teams })   // 一次导入角色 + 编队
```

`addPresets()` / `addTeams()` 支持批量导入，可作为从其它来源补数据的入口。
